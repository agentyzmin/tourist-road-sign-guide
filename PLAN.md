- 103 ілюстрації як PNG (1800–2400 px) у `docs/assets/img/<розділ>/`, збігаються з `INDD/assets/PNG`.

- SVG піктограм: viewBox 226.77, група `#bg` (коричневий #592d2c) + група `#icons` (білий гліф). З неї легко отримати прозору та контурну версію.

## 3. Рішення щодо стеку

**Рекомендація: лишитися на Docsify** і додати інтерактив як невеликі vanilla-JS модулі (custom elements / Docsify-плагіни), а підготовку іконок винести в скрипт збірки.

Чому: контент уже в markdown під Docsify, деплой простий (статичні файли по FTP), обсяг гайда невеликий. Міграція на Astro/VitePress дала б SSR і кращий SEO, але це велика робота без прямої користі для задачі. Якщо згодом SEO стане критичним, markdown переноситься майже без змін.

Умова: Docsify рендерить HTML усередині markdown, тому `<icon-gallery>`, `<poi-calculator>` тощо вставляються прямо в `.md`. Модулі треба ініціалізувати через хук `doneEach`, бо сторінки підвантажуються без перезавантаження.

## 4. Етапи

### Етап 0. Технічна гігієна (малий)

- `index.html`: `lang="uk"`, абсолютний OG URL, зафіксувати версії (`docsify@4.13.x` і плагіни), прибрати GA або додати id, видалити мертвий код форми.
- Workflow: оновити actions, додати крок перевірки битих посилань/зображень (опційно).
- Стабільні id заголовків через `:id=` латиницею, переписати `_sidebar.md` і внутрішні посилання на них.
- Додати `robots.txt`, `sitemap.xml`, повний `404.md`.

### Етап 1. Довести контент до відповідності PDF (малий)

- Вставити підписи 7.5 і 7.7, відновити нумерацію 7.2.1 / 7.2.4 / 7.2.5 / 7.3.3 за PDF.
- Виправити заголовки розділу 1 і 5.4.
- Пройтися по кожному розділу поруч із PDF: примітки, виноски (напр., `*` і `**` у таблиці транслітерації), типографіка (нерозривні пробіли, лапки, тире).
- Заповнити `alt` змістовним текстом (можна з підписів).
- Перевірити, чи PDF 1.0 (червень 2022) відповідає останнім INDD: в `archive/` є правки 7-Design-TypeA за 2022-05. Якщо INDD новіший за PDF, джерелом правди стає INDD (експорт IDML → текст).

### Етап 2. Бібліотека піктограм із завантаженням (середній) — головний інтерактив

**Дані.** `docs/data/icons.json`: для кожної з 57 піктограм `slug`, `name_uk`, `name_en` (опційно), `section` (категорії / додаткові / сервіси), `group` (назва категорії з Додатка А), `kind` (загальна / окрема), `formats`. Мапінг slug ↔ українська назва робиться за Додатком А і файлом `Tourist Road Signs - Icons.pdf`. Відкриті випадки: `memorial`, `land-object` — у PDF є підкатегорія, але в Production лише один файл; `dart-top10/30/100` є у Production, але відсутні в Додатку А.

**Скрипт збірки** `scripts/build-icons.{py|mjs}` (запускається локально, результат комітиться):
1. Копіює з Drive у `docs/icons/{svg,png,eps,pdf}/<slug>.<ext>` з короткими іменами.
2. Генерує похідні SVG: `svg-transparent/` (без групи `#bg`), `svg-outline/` (чорний контур на білому) — за потреби.
3. Копіює повний набір: `docs/icons/all/TouristRoadSigns-Icons.{dwg,ai,pdf}`.
4. Збирає ZIP: по форматах і загальний.
5. Перевіряє, що для кожного slug є всі 4 формати, і пише `icons.json`.

**UI** `docs/js/icon-gallery.js` + сторінка `appendix-a-icons.md` (аліас `/icons` вже є):
- Сітка карток з групуванням як у PDF (категорія → загальна + окремі), фільтр за розділом, пошук за назвою.
- Картка: превʼю (коричневе / контурне на сітці, як у PDF), назва, кнопки SVG / PNG / EPS / PDF, «Копіювати SVG».
- Зверху: «Завантажити все» (ZIP по форматах, DWG, AI, PDF-каталог), короткі правила використання та ліцензія.
- Ті самі файли використовуються інлайн у 2.1 (іконка біля категорії) і 2.4 (замість заглушок) через `<img src="icons/svg/…">` або маленький `<icon name="…">`.

### Етап 3. Інтерактивні елементи в тексті (середній)

Пріоритет за користю для проєктувальника:

1. **Калькулятор значущості точки інтересу** (2.1.6–2.1.7): чекбокси критеріїв → сума балів → гранична відстань з таблиці 2.1, плюс підказка про обовʼязкові умови 2.1.10.
2. **Інтерактивна матриця типів знаків** (таблиця 4.1): клік по A1…C3 → приклад знака, що робить, посилання на 4.x / 5.x / 7.x. Та сама навігація «тип знака → три розділи» у вигляді плашки вгорі відповідних підрозділів.
3. **Якорі на нумерованих абзацах**: `.p-number` стає посиланням з `id="p-2-1-7"`, копіювання посилання по кліку. Потрібно для цитування гайда в проєктах.
4. **Транслітератор** (6.3): поле вводу → транслітерація за модифікованою КМУ 2010 з правилами таблиці 6.1 і винятками (`щ → sch`, позиційні `й/я/ю/є`, апостроф). Правила треба звірити з приміткaми в PDF.
5. **Калькулятор розмірів знака** (розділ 7): ввід висоти літери h_в → розміри елементів. У тексті лише ~10 згадок кратних h_в, більшість розмірів у кресленнях. Робити лише якщо витягнемо розмірні ланцюжки з `.ai` креслень — інакше пропустити.

Усі модулі: vanilla JS, без збірки, окремий файл на модуль, ініціалізація в `doneEach`.

### Етап 4. Полірування (малий–середній)

- Оптимізувати PNG (oxipng/pngquant), додати WebP з `<picture>`; розглянути експорт креслень розділу 7 у SVG з `.ai` — чіткість при зумі.
- Print-стилі (гайд часто друкують фрагментами).
- Мобільна перевірка таблиць 4.1 і 6.1, абсолютного позиціонування `.p-number` і `.left-col`.
- Lighthouse-прогін, перевірка контрасту кастомних кольорів.
- Оновити `README.md`: як редагувати контент, як перезібрати іконки, як деплоїться.
